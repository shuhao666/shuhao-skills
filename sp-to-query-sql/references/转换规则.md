# 存储过程 → 接口查询SQL统一转换规范（增强版·修订）

## 一、总体转换目标

| 原存储过程（SP） | 目标查询SQL（接口ETL） |
|------------------|------------------------|
| 过程化落地脚本：删数据 → 临时表缓存 → INSERT入库 → 后置UPDATE清洗 | **纯只读、无DML查询SQL**，直接返回结果集 |
| 包含变量声明、条件判断、事务控制 | 无过程化逻辑，仅包含 `WITH CTE` + `SELECT`（**必要时允许使用临时表物化中间结果，但禁止写入最终业务表**） |
| 依赖物理临时表、索引提示 | 使用逻辑CTE或临时表（仅限`#temp`），仅保留 `NOLOCK` 提示 |
| 参数带默认值逻辑 | 使用外部占位符 `${KSSJ}`、`${JSSJ}`，由调用方赋值 |
| 数据写入物理表 | **直接输出结果集，不落地** |

**核心原则**：剔除过程化、落地逻辑；后置清洗全部内联到SELECT；物理临时表优先转CTE（大数据量可降级为临时表）；参数改为占位符。

## 二、分大类标准化转换规则

### 规则1：存储过程头尾 & 过程化代码全部删除

**删除内容**：
- 数据库上下文：`USE [HOSPITAL_DW]`、`GO`
- 存储过程定义：`CREATE PROC` / `ALTER PROC`、参数列表、`AS`、`BEGIN`、`END`
- 配置语句：`SET ANSI_NULLS ON`、`SET QUOTED_IDENTIFIER ON`
- 变量声明与赋值：`DECLARE @kssj...`、`SET @kssj = ...`
- 条件判断与默认值逻辑：`IF(@ksrq=''...)` → 完全移除，由外部程序提供完整时间范围
- 事务控制：`BEGIN TRANSACTION`、`COMMIT`、`ROLLBACK`

**替换为**：
- 文件头部增加脚本说明注释（接口名称、原始存储过程名、参数说明、转换日期）
- 参数直接使用占位符：`${KSSJ}`、`${JSSJ}`（格式：`yyyy-mm-dd HH:MM:SS`）

**示例**：
```sql
-- 原SP
CREATE PROC [dbo].[usp_xxx] @ksrq varchar(20)='', @jsrq varchar(20)='' AS
BEGIN
    DECLARE @kssj varchar(20)
    IF(@ksrq='') SET @kssj = CONVERT(varchar(10),GETDATE()-1,120)+' 00:00:00'
    ELSE SET @kssj = CONVERT(varchar(10),@ksrq,120)+' 00:00:00'
    ...
END

-- 转换后
-- ============================================
-- 查询名称：门诊首页信息接口
-- 原始存储过程：usp_xxx
-- 参数：${KSSJ}（开始时间）, ${JSSJ}（结束时间），格式如 '2026-06-04 00:00:00'
-- ============================================
```

### 规则2：临时表处理（允许CTE或临时表，优先CTE）

| 原模式 | 转换后（优先CTE） | 备选（大数据量性能优化） |
|--------|------------------|--------------------------|
| `SELECT ... INTO #tmp FROM ...` | `WITH cte_tmp AS (SELECT ... FROM ...)` | 保持 `SELECT ... INTO #tmp`，但**不能写入最终业务表**，查询结束后需显式 `DROP` |
| `DROP TABLE #tmp` | 无需删除（CTE自动释放） | 会话结束后自动释放，或显式 `DROP` |

**注意**：
- 临时表名映射：`#VW_XXX` → `cte_VW_XXX`
- 移除 `INDEX([...])` 显式索引提示，仅保留 `WITH(NOLOCK)`
- 筛选条件（时间范围、业务状态）与原临时表创建逻辑保持一致
- **性能优化建议**：当基础表数据量较大（超过10万行）且后续需要多次访问该数据时，**允许使用临时表物化中间结果**，以避免CTE被反复扫描。但必须遵守：
  - 临时表仅用于当前查询会话，不持久化
  - 查询结束前显式删除临时表
  - 在临时表上创建主键或聚集索引（如 `PRIMARY KEY (xh)`）加速连接

**示例**：
```sql
-- 方式1：纯CTE（小数据量或简单场景）
WITH cte_VW_CQYZK AS (
    SELECT * FROM VW_CQYZK WITH(NOLOCK)
    WHERE lrrq BETWEEN ${KSSJ} AND ${JSSJ}
)
SELECT ... FROM cte_VW_CQYZK ...

-- 方式2：临时表（大数据量，需物化）
SELECT * INTO #tmp_VW_CQYZK
FROM VW_CQYZK WITH(NOLOCK)
WHERE lrrq BETWEEN ${KSSJ} AND ${JSSJ};

CREATE INDEX idx_tmp_xh ON #tmp_VW_CQYZK(xh);

-- 后续查询使用 #tmp_VW_CQYZK，最后 DROP TABLE #tmp_VW_CQYZK;
```

### 规则3：后置UPDATE数据清洗 → 全量内联至SELECT字段

**核心原则**：原SP中所有在 `INSERT` 之后的 `UPDATE` 语句，都必须在 `SELECT` 列中直接计算出最终值。

#### ⚠️ 3.0 UPDATE转JOIN/子查询的关键原则（最重要·新增）

**问题背景**：原SP中的UPDATE语句从其他表获取字段值（如医保编码），转换时常见错误：

| 转换方式 | 问题 | 正确方案 |
|----------|------|----------|
| `LEFT JOIN 表 ON 条件` | **多行匹配导致数据膨胀**，即使加 DISTINCT 也无法正确去重（字段值不同） | 使用子查询 `SELECT TOP 1` 或 `OUTER APPLY` |
| 直接"修正"原SP逻辑 | **违反规则0**，原SP的"错误"逻辑必须原样保留 | 分析原SP条件，严格按原逻辑转换 |

**示例对比**：

```sql
-- ❌ 错误1：LEFT JOIN 导致数据膨胀
SELECT DISTINCT ...
FROM base fx
LEFT JOIN YK_YPCDMLK ypcdm ON fx.idm = 0 AND fx.idm = ypcdm.idm
LEFT JOIN YY_SFXXMK sfxx ON fx.idm <> 0 AND fx.ypdm = sfxx.id
-- 问题：多行匹配产生笛卡尔积，DISTINCT无法去重（dydm值可能不同）

-- ❌ 错误2：逻辑与原SP相反
-- 原 UPDATE 条件：xmlb=0(idm<>0)时从YK_YPCDMLK获取
-- 转换时"修正"为：idm=0→YK_YPCDMLK（逻辑反了！）

-- ✓ 正确：使用子查询确保一对一，并保持原SP逻辑
SELECT ...,
    CASE
        WHEN fx.idm <> 0 THEN ISNULL((
            SELECT TOP 1 ypcdm.dydm
            FROM YK_YPCDMLK ypcdm WITH(NOLOCK)
            WHERE ypcdm.idm = fx.idm AND ISNULL(ypcdm.dydm, '') <> ''
        ), '')
        ELSE ISNULL((
            SELECT TOP 1 sfxx.dydm
            FROM YY_SFXXMK sfxx WITH(NOLOCK)
            WHERE sfxx.id = fx.ypdm AND ISNULL(sfxx.dydm, '') <> ''
        ), '')
    END AS mxxmbmyb
FROM base fx
-- 无LEFT JOIN，数据量与原SP一致
```

**判断标准**：
- 原UPDATE从单表获取单字段 → 使用子查询 `(SELECT TOP 1 ...)`
- 原UPDATE从单表获取多字段 → 使用 `OUTER APPLY (SELECT TOP 1 ...)`
- 原UPDATE涉及复杂聚合 → 使用独立CTE + LEFT JOIN

#### 3.1 空值/空串 → 默认值

**统一模板**：
```sql
-- 字符串字段（需trim后判断空串）
COALESCE(NULLIF(RTRIM(LTRIM(字段)), ''), '默认值')

-- 日期字段
COALESCE(日期字段, '1900-01-01')
```

**常见场景对照**：

| 原SP后置UPDATE | 转换后SELECT内联表达式 |
|----------------|------------------------|
| `update set yzlx='99' where yzlx='' or yzlx is null` | `COALESCE(NULLIF(CASE ... END, ''), '99') AS yzlx` |
| `update set ypgg='-' where ypgg='' or ypgg is null` | `COALESCE(NULLIF(SUBSTRING(ypgg,1,64), ''), '-') AS ypgg` |
| `update set hzzs = ISNULL(convert(varchar(500), ...), '1')` | `COALESCE(CONVERT(VARCHAR(500), SUBSTRING(...), 1, 500)), '1') AS hzzs` |

#### 3.2 特殊值映射（如 `'ONCE'` → `'ST'`）

**原SP**：
```sql
UPDATE v13_tb_cis_dradvice_detail SET yypcdm='ST' WHERE yypcdm='ONCE'
```

**转换后**：
```sql
CASE WHEN pc.[name] = 'ONCE' THEN 'ST' ELSE pc.[name] END AS yypcdm
```

#### 3.3 复杂后置逻辑内联（主诉、过敏史、诊断等）

原SP中这类更新往往涉及多表关联，应转换为**独立的派生表（CTE）**，然后在最终查询中 `LEFT JOIN` 主表，并使用 `COALESCE` 覆盖默认值。

**示例：主诉更新**
```sql
-- 原SP
UPDATE a SET a.hzzs = ISNULL(CONVERT(VARCHAR(500), SUBSTRING(B.wbnr,1,500)), '1')
FROM #ghzdk a
JOIN OUTP_JZJLK A ON a.xh = A.ghxh
JOIN EMR_OUTP_BLWJJGNRK B ON ...

-- 转换后（CTE）
hzzs_cte AS (
    SELECT A.ghxh AS xh,
           COALESCE(CONVERT(VARCHAR(500), SUBSTRING(B.wbnr,1,500)), '1') AS hzzs
    FROM OUTP_JZJLK A
    JOIN EMR_OUTP_BLWJJGNRK B ON ...
    WHERE B.wjjgdm = 'DLDM.280'
)
-- 最终 SELECT 中：
COALESCE(h.hzzs, '1') AS hzzs
```

#### 3.4 诊断信息的多行转一行（条件聚合）

原SP中通过多次UPDATE从诊断表获取主诊断和辅助诊断，转换时应使用 `MAX(CASE WHEN ...)` 聚合，每个 `xh` 输出一行。

```sql
diag_cte AS (
    SELECT ghxh AS xh,
           MAX(CASE WHEN zdlx=0 AND zdlb=0 THEN ISNULL(SUBSTRING(zdmc,1,100),'-') END) AS mzzzyzd,
           MAX(CASE WHEN zdlx=0 AND zdlb=0 THEN ISNULL(zddm,'-') END) AS mjzzyzdmb,
           MAX(CASE WHEN zdlx=1 AND zdlb=0 THEN ISNULL(SUBSTRING(zdmc,1,500),'-') END) AS mjzqtzd,
           ...
    FROM VW_SF_YS_MZBLZDK
    GROUP BY ghxh
)
```

### 规则4：关联、WHERE过滤、UNION ALL结构完整保留

#### 4.1 关联表与过滤条件
- `JOIN` / `LEFT JOIN`：表名、别名、关联条件 **1:1** 原样迁移。
- 业务过滤条件（如 `yz.yzzt <> 3`、`sy.brzt <> '9'` 等）**必须保留**。
- 原SP中可能存在的冗余日期范围过滤（例如在后续UPDATE中再次过滤 `ghrq BETWEEN ...`），因为基础CTE已经过滤，**建议移除**以避免重复扫描。

#### 4.2 UNION ALL 结构
- 两个分支（如长期医嘱、临时医嘱）必须保持原顺序与完整性。
- 每个分支内字段数量、类型、顺序必须一致。
- **必须为每个分支添加 `DISTINCT`**，因为原SP依赖目标表的唯一约束去重，纯查询需要显式去重。

#### 4.3 ⚠️ DISTINCT 使用规则（新增·重要）

| 场景 | 是否使用DISTINCT | 原因 |
|------|------------------|------|
| UNION ALL 多分支去重 | **必须使用** | 原 SP 依赖目标表唯一约束去重 |
| LEFT JOIN 多表关联 | **禁止使用** | 多行匹配会导致不同字段值，DISTINCT 无法正确去重 |
| 原SP无DISTINCT/去重机制 | **禁止使用** | 会改变原数据量，导致结果不一致 |
| 子查询替代LEFT JOIN后 | **不需要** | 子查询确保一对一，无需去重 |

**关键原则**：
- `DISTINCT` 仅用于 **UNION ALL 分支去重**
- 若 LEFT JOIN 产生多行匹配，**应改用子查询/OUTER APPLY**，而非依赖 DISTINCT
- DISTINCT 去重基于所有字段值，若关联表字段不同，无法达到预期去重效果

**错误示例**：
```sql
-- ❌ 错误：LEFT JOIN多行匹配，DISTINCT无法正确去重
SELECT DISTINCT a.xh, b.dydm  -- dydm可能不同，无法去重
FROM base a
LEFT JOIN code_table b ON a.idm = b.idm  -- 若b有3行匹配a，会产生3行

-- ✓ 正确：使用子查询确保一对一
SELECT a.xh,
    (SELECT TOP 1 dydm FROM code_table WHERE idm = a.idm) AS dydm
FROM base a
```

#### 4.4 字段映射对照（以医嘱为例）

| 分支 | yzid前缀 | yzlb规则 |
|------|----------|----------|
| 长期医嘱（CQ） | `'cq' + CONVERT(VARCHAR, yz.xh)` | `CASE WHEN yz.yzlb=12 THEN 3 ELSE 1 END` |
| 临时医嘱（LS） | `'ls' + CONVERT(VARCHAR, yz.xh)` | `CASE WHEN yz.yzlb=12 THEN 3 ELSE 2 END` |

### 规则5：常量、硬编码字段原样保留

- 固定字符串：`'JKGKHSKP'`、`'-'`（**注意是单横线，不是双横线**）、`'0'`、`'1'` 等直接使用。
- 拼接常量：`'cq'`、`'ls'`、`SUBSTRING('42503274500', 10, 2)` 完全保留。
- 数值常量：`0`、`1`、`3` 等不做修改。
- 业务固定逻辑：皮试判别 `'0'`、修改标志 `1` 等保持原值。

---

### 规则6：字段列表与注释处理

#### 6.1 字段顺序严格对齐
- 原SP中 `INSERT INTO 目标表 (字段列表) SELECT ...`，转换后抛弃 `INSERT`，**必须保持 `SELECT` 后的字段顺序与原目标表字段顺序完全一致**，否则会导致下游对接错位。

#### 6.2 注释清理
- 删除原SP中的行内注释（`--` 说明性注释），保留重要业务注释（如字段含义）。
- 在SQL文件头部增加统一注释，包含：
  - 查询名称
  - 原始存储过程名称
  - 参数说明（含占位符格式）
  - 转换日期
  - 依赖的表/视图说明

---

### 规则7：移除索引提示与锁优化

- 删除所有 `INDEX([...])` 提示，因为CTE或复杂查询中优化器可能忽略此类强制提示。
- **保留 `WITH(NOLOCK)`** 以避免锁争用，保持读未提交语义。
- 若原SP使用 `WITH(READUNCOMMITTED)`，同样保留。

---

### 规则8：性能优化专项指南（新增）

#### 8.1 避免重复扫描基础表

原SP中的临时表 `#ghzdk` 被后续多个UPDATE重复使用，转换时如果全部写成CTE，会导致基础表被多次扫描。**优化策略**：

- **策略A（推荐）**：将基础数据物化为临时表（`SELECT ... INTO #base`），并创建主键索引。后续CTE或子查询直接引用该临时表，而不是原始大表。
- **策略B（纯CTE）**：将每个补充数据源（主诉、过敏史、费用等）写成独立的CTE，这些CTE直接从**原始源表**获取数据（而非从基础CTE派生），避免多层嵌套。最终通过 `LEFT JOIN` 关联。

**判断标准**：
- 基础表行数 < 10万 → 优先使用纯CTE。
- 基础表行数 > 10万 或 后续关联复杂 → 使用临时表物化。

#### 8.2 派生表独立性

每个补充数据源（如主诉、过敏史、诊断、药品标志）应定义为独立的CTE，其数据来源应直接取自原始业务表（或已经过日期过滤的视图），**不要依赖其他CTE的结果**，以避免查询计划中的重复假脱机。

**错误示例**：
```sql
WITH base AS (...),
     hzzs AS (SELECT ... FROM base ...)  -- 依赖base，会导致base被重复扫描
```
**正确示例**：
```sql
WITH base AS (...),
     hzzs AS (SELECT ... FROM OUTP_JZJLK ... WHERE ghxh IN (SELECT xh FROM base))  -- 仅使用base的键值
```
或更优：`hzzs` 直接从 `OUTP_JZJLK` 关联 `VW_GHZDK`（日期过滤后的副本）。

#### 8.3 费用明细聚合注意点

费用明细的CTE中，`GROUP BY` 必须只包含主键字段（如 `xh`），**不能包含 `ee_id`、`hh_id` 等分类字段**，否则每个xh会返回多行，造成结果集膨胀。

```sql
-- 错误
GROUP BY xh, ee_id, hh_id

-- 正确
GROUP BY xh
```

#### 8.4 避免标量子查询，改用`LEFT JOIN`或`OUTER APPLY`

原SP中某些UPDATE使用了标量子查询（如 `(SELECT TOP 1 ... FROM ... WHERE ...)`），转换时应改为 `OUTER APPLY (SELECT TOP 1 ... )` 或事先聚合为CTE。

**示例**：
```sql
-- 低效
SELECT (SELECT TOP 1 zdmc FROM VW_SF_YS_MZBLZDK WHERE ghxh = a.xh AND zdlx=0) AS mzzzyzd

-- 高效
OUTER APPLY (SELECT TOP 1 zdmc FROM VW_SF_YS_MZBLZDK WHERE ghxh = a.xh AND zdlx=0 ORDER BY ...) d
```

#### 8.5 尾差处理内联

原SP最后对 `zfje` 和 `qtf` 的调整逻辑，应内联到最终SELECT中：

```sql
CASE WHEN (zfje_calc > mjzzf_calc AND zfje_calc - mjzzf_calc < 0.1) THEN mjzzf_calc ELSE zfje_calc END AS zfje,
(mjzzf_calc - (ybylfwf_calc + ...)) AS qtf
```

### 规则9：字段映射验证（新增）

转换完成后，必须对比原始存储过程中 `UPDATE` 语句修改的字段名与CTE中输出的字段名是否一致。常见错误：

- 原SP更新 `sfsy`，CTE中误写为 `sfys`
- 原SP更新 `hzzs`，CTE中误写为 `hzsz` 或 `hzzs_val`
- 常量默认值错误：原SP使用 `'-'`，CTE中误写为 `'--'`

**建议**：在转换过程中，建立一个字段对照表，逐一核对。

## 三、转换前后差异对照表（修订版）

| 维度 | 原存储过程 | 转换后查询SQL | 关键动作 |
|------|------------|---------------|----------|
| 执行目标 | 落地物理表（INSERT/DELETE） | 直接返回结果集（SELECT） | 删除所有DML |
| 数据源 | 物理临时表（#Temp） | 逻辑CTE **或** 会话级临时表 | 临时表转CTE，大数据量允许临时表 |
| 参数处理 | 内部变量 + 默认值逻辑 | 外部占位符 `${KSSJ}`,`${JSSJ}` | 剥离参数默认值 |
| 空值处理 | 后置UPDATE语句 | SELECT中 `COALESCE/NULLIF` | 逻辑前移 |
| 特殊值映射 | 后置UPDATE（如 ONCE→ST） | SELECT中 `CASE WHEN` | 逻辑前移 |
| 索引提示 | 强制索引 `INDEX=[...]` | 仅保留 `NOLOCK` | 去索引硬绑定 |
| 去重 | 依赖目标表约束隐式去重 | 显式 `DISTINCT` | 增加去重 |
| 性能优化 | 无（依赖过程化步骤） | 物化中间结果、独立派生表、条件聚合 | 避免重复扫描 |
| 代码规模 | 过程化、多步骤 | 声明式、单条查询（可拆分临时表） | 简化维护 |
